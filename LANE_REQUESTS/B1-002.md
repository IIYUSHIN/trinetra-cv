# ERR-CL-017 — guarded visible API and validation responsibility (PROPOSED)

Impact: IMP-0399..0420 and future evaluator/custodian consumers. No empirical threshold or policy mapping is proposed.

1. **Visible parser boundary.** The visible public value uses a frozen/strict/closed internal DomainModel and guarded constructor/native/JSON loaders. Third-party schema adaptation is explicitly refused before input parsing: an external JSON parser otherwise fails before a model validator can sanitize its errors. Existing field access, evolve, JCS and visible JSON export remain available. Cost: consumers must use the guarded API rather than TypeAdapter or assume the public facade is a BaseModel. Principal review must ratify this interface choice.
2. **Sealing is a low-level primitive.** PrivateTruthBundle validates the structural payload and crypto authenticates the caller-supplied commitment digest and population label. It does not prove truth/oracle membership or correspondence to a signed population commitment. Before any run qualification, Codex B's later I12 run-manifest/harness work and Codex A's I16/I17 authorization must verify those correspondences with the custodian. Cost if omitted: valid encryption of the wrong authored bundle. No validated-population claim is made here.
3. **Oracle science.** These schemas enforce state dimensions and explicit set constraints, not a new universal assessability/capability-to-verdict mapping. Profile-specific oracle construction/validation belongs to the later I12 behavioral-validation/harness/acceptance packets and frozen Claim/Test/Policy profiles. Cost if omitted: a structurally valid but scientifically wrong authored oracle. No scoring or qualification may treat schema construction alone as scientific validation.
4. **Declared lineage.** Closure validates declared leakage edges. It cannot establish undeclared real-world ancestry or bind a population's EIG references to actual components by itself. Later I12 generators/provenance and I16/I17 campaign authorization must establish complete declarations and membership correspondence. Cost if omitted: false independence from missing or misbound lineage. No real population was built or qualified.
5. **Empty populations/private reconstruction.** Empty synthetic manifests describe zero membership; they do not qualify. Private JSON dictionaries contain arrays, while native constructors deliberately require tuples. There is no general private from-wire API in this lease; later authorized private export/reconstruction must define and validate that boundary. Cost: consumers must not assume constructor round trips or qualification from an empty manifest.
6. **Evaluator process trust.** Explicit private reads, private-schema imports, raw-key functions and privileged Python reflection remain evaluator authority. Object barriers prevent incidental export; they do not isolate hostile Python in that process. Cost: physical production separation still requires independently tested mounts, environment and IPC controls.
7. **Wire interoperability.** ERR-CL-014/015/016 remain PROPOSED. Locally passing transcripts and catalogs do not ratify them. Cost: principal/custodian changes require retesting consumers before integration acceptance.
8. **Scan scope/resources.** The scanner covers the documented raw/encoded/ZIP/USTAR/gzip profiles and explicit inspection-byte/entry/depth budgets. Arbitrary encodings, unsupported compression, concurrent filesystem races and measured peak CPU/memory bounds are unqualified. ZIP directory metadata and JSON parsing occur before all inspection counters apply. Caller release qualification must identify supported immutable artifacts; unsupported images/formats require separately qualified unpacking/scanning. Actual runner/web/container releases and physical/empirical qualification remain NOT_RUN. Cost: a known-profile scan must not be advertised as a universal release or resource certificate.

Proposed resolution: principal review ratifies or revises these API/ownership contracts before downstream scientific or interoperable handoff. All work remains contingent; no acceptance status changes.
